## ICMP Configuration

### Block ICMP Echo-Request (Ping) while allowing essential ICMP types

---
    # Allow ping from WireGuard VPN (must come before the drop rule)
    iifname "wg0" ip protocol icmp icmp type echo-request accept

    # Drop ping, permit fragmentation-needed
    ip protocol icmp icmp type echo-request drop
    ip protocol icmp icmp type destination-unreachable accept

    # ... other rules ...
---

### Rationale

Blocking ICMP Echo-Request reduces visibility to automated internet-wide scanners (e.g. Shodan, Censys, botnet sweeps) that use ping to identify live hosts before launching targeted attacks. This significantly cuts down on follow-up port scans and brute-force attempts.

However, fully blocking all ICMP traffic breaks **Path MTU Discovery** — when an intermediate router cannot forward a packet due to size limits, it sends an ICMP `Destination Unreachable (Fragmentation Needed)` message back. Without it, TCP connections silently stall on large transfers (classic MTU black hole). Therefore, `destination-unreachable` is explicitly allowed through.

### Important: Rule ordering and `flush ruleset`

Two things caused issues during setup:

1. **Rule ordering matters.** NFTables evaluates rules sequentially. The `echo-request drop` rule must appear **before** any generic `ip protocol icmp accept` rule — otherwise all ICMP traffic (including ping) gets accepted before the drop rule is ever reached.

2. **`flush ruleset` is required at the top of `/etc/nftables.conf`.** Without it, `nft -f` appends rules to the existing ruleset instead of replacing them, leading to duplicated chains where stale rules shadow new ones. Always start the config file with `flush ruleset` to ensure a clean state on every reload.

### VPN exclusion

Pings from within the WireGuard VPN should still work for diagnostics. A dedicated `accept` rule for `iifname "wg0"` placed **before** the global drop rule ensures VPN traffic is exempt from the ping block:

nft iifname "wg0" ip protocol icmp icmp type echo-request accept
